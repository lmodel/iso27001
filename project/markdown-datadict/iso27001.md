
# ISO27001


**metamodel version:** 1.12.0

**version:** 2022/Amd 1:2024


A LinkML model of the records an organization keeps to run an information security management system (ISMS) to ISO/IEC 27001:2022 with Amendment 1:2024: its context and scope, policies, roles and objectives, risks and their treatment, its controls and Statement of Applicability, the support and operation it needs, its audits and management reviews, and its nonconformities, corrective actions and improvements. The 93 reference controls of Annex A appear by their numbers alone.

## Base Classes


Foundational classes in the hierarchy (root classes and direct children of Thing):

| Class | Description |
| --- | --- |
| [IsmsApplicabilityEntry](#IsmsApplicabilityEntry) | One entry of the Statement of Applicability, which either includes a control or excludes an Annex A control, and says why. |
| [IsmsSecurityEvent](#IsmsSecurityEvent) | An information security event someone reported, and the assessment of whether it is an incident. An event assessed as an incident is recorded as an IsmsSecurityIncident. |

## Standalone Classes


These classes are completely isolated with no relationships and are not used as base classes:

| Class | Description |
| --- | --- |
| [IsmsExcludedControl](#IsmsExcludedControl) | An entry that leaves out an Annex A control the organization does not need, and says why. |
