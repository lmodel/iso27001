# Playbooks

* [Regenerate and test after a schema change](regenerate-and-test.md) - How to change the schema and check it: `uv sync --group dev`, edit `src/iso27001/schema/iso27001.yaml`, then `just lint`, `just gen-project`, `just gen-doc`, `just create-empty-overlay`, `just lokf-adapt` and `just test`, and the pre-commit hooks before a pull request.
* [Validate ISMS data against the schema](validate-data.md) - How to check a file of ISMS records with `linkml-validate -s src/iso27001/schema/iso27001.yaml -C <Class>`, why dates are written quoted, and what the generated dataclasses and Pydantic models leave unchecked.
* [Update the upstream pins](update-upstream-pins.md) - What to do when the Upstream watch reports that ISO published a new amendment, corrigendum or edition of ISO/IEC 27001, changed a pinned record's stage, named a successor, or changed the dataset's licence: replace the ISO Open Data extract and move the pins in `scripts/check_upstream_release.py` and the schema header together.
* [Merge the standard's text into a private copy](merge-licensed-text.md) - How a holder of a licence to ISO/IEC 27001 fills a private copy of the overlay scaffold `iso27001-overlay.template.yaml` with the standard's wording and merges it with `just overlay-licensed-text` into `tmp/iso27001-merged.yaml`, which git ignores and which is never distributed.
* [Cut a release](release.md) - How a release is made: Conventional Commits on `main`, an `## [Unreleased]` changelog section, the `v0.0.0` baseline tag that keeps the first release at 0.1.0, and `semantic-release.yml`, which tags the release and dispatches Knowledge Release to attach `schema-<tag>-iso27001.yaml` once `KNOWLEDGE_RELEASE_ENABLED` is true.
* [Knowledge sources map](knowledge-sources.md) - The librarian's scrape map: every repository location and external page this bundle derives concepts from, the concepts each yields, how to re-check each on a refresh run, and the paths left out on purpose.
